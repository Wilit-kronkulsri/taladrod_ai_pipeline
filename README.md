# TaladRod AI Pipeline

> งานทดสอบตำแหน่ง AI Data Engineer (Data Collection & Analysis)

## 1. โปรเจกต์นี้คืออะไร

โปรแกรมที่ดึงประกาศรถมือสองจาก [taladrod.com](https://www.taladrod.com/w40/isch/schc.aspx?fno:new) สูงสุด 100 ประกาศต่อรอบ พร้อมรูปทุกรูป แล้ว

1. **จัดประเภทรถ** (เก๋ง, กระบะ, SUV/PPV, รถตู้/MPV, อื่นๆ)
2. **ให้คะแนนคุณภาพรูปทุกรูป** เต็ม 10 ด้วยโมเดล AI ที่ **รันบนเครื่องนี้ทั้งหมด** ไม่เรียก API ภายนอก
3. **สรุปผลเป็นไฟล์ JSON** และมีหน้า Dashboard สำหรับดูผลและสั่งดึงข้อมูลชุดใหม่

**ชุดที่ส่งมามีผลรันจริงอยู่แล้ว** (14 พ.ย. 2026) เปิด Dashboard แล้วเห็นข้อมูลทันที ไม่ต้องรันใหม่

| รายการ | ค่า |
|---|---|
| ประกาศ | 100 |
| รูป | 1,320 (ทุกรูปมีคะแนน, โหลดไม่สำเร็จ 0) |
| ประเภทรถ | เก๋ง 41 · SUV/PPV 38 · กระบะ 10 · รถตู้/MPV 7 · อื่นๆ 4 |
| ชนิดรูป | ภายใน 585 · ภายนอก 580 · ห้องเครื่อง 83 · ชิ้นส่วนระยะใกล้ 50 · เอกสาร/อื่นๆ 22 |
| คะแนนรูป | ต่ำสุด 5.3 · ค่ากลาง 7.6 · สูงสุด 7.9 |
| เวลาที่ใช้ | ดึงข้อมูลราว 55 นาที · ให้คะแนน 11 นาที (CPU) |

ดูรูปเทียบกับคะแนนได้ที่ [docs/iqa_sanity.md](docs/iqa_sanity.md) (รูปในรายงานนี้ชี้ไปที่ `output/images/` ของชุดที่ส่งมา ถ้าดึงชุดใหม่แล้ว ให้รัน `taladrod sanity` เพื่อสร้างรายงานใหม่)

**ครั้งต่อไป** เปิดได้ทันที

ปิดโปรแกรมโดยปิดหน้าต่างสีดำ

**สิ่งที่จะเห็นใน Dashboard**

## 4. ดึงข้อมูลชุดใหม่

กดปุ่ม **Run all** ที่แถบซ้าย แล้วรอ ระบบจัดการที่เหลือให้เอง

| สถานะของชุดปัจจุบัน | กด Run all แล้วเกิดอะไร |
|---|---|
| ครบแล้ว (เช่น 100 จาก 100) | เก็บชุดเดิมไว้ใน `output_archive/` แล้วดึงชุดใหม่ ใช้เวลาราว 1 ชั่วโมงสำหรับ 100 ประกาศ |
| ยังไม่ครบ (หยุดกลางทาง) | ทำต่อจากเดิม ไม่ดึงประกาศที่มีแล้วซ้ำ |

แถบซ้ายจะบอกก่อนกดเสมอว่าจะเกิดอะไร ก่อนเก็บชุดเดิม ระบบจะลองเปิดเว็บต้นทางก่อน ถ้าเข้าไม่ได้ (เน็ตหลุดหรือโดนบล็อก) จะไม่ย้ายอะไรเลย

**ระหว่างรัน อย่ากดอะไรในหน้า Dashboard** การกดตัวกรองหรือปุ่มอื่นจะหยุดงานกลางทาง ถ้าหยุดไปแล้ว กด Run all อีกครั้งเพื่อทำต่อ

**ชุดเก่า**
- อยู่ที่ `output_archive/<วัน_เวลา>/` เช่น `output_archive/2026-11-14_1913/`
- ระบบเก็บไว้ **3 ชุดล่าสุด** ชุดที่เก่ากว่าถูกลบเอง แถบซ้ายจะเตือนชื่อชุดที่จะถูกลบก่อนทุกครั้ง (แบบ command line จะแจ้งชื่อชุดที่ลบหลังลบแล้ว)
- โฟลเดอร์อื่นที่คุณวางไว้ใน `output_archive/` เอง ระบบไม่นับและไม่ลบ
- เปิดดูชุดเก่าได้จากตัวเลือก **"ชุดข้อมูล"** ที่แถบซ้าย ระหว่างดูชุดเก่า ปุ่มรันจะถูกปิด
- หนึ่งชุดใช้ที่ราว 130MB แถบซ้ายแสดงขนาดรวมของชุดเก่า และเตือนเมื่อที่ว่างในดิสก์เหลือน้อยกว่า 2GB

**ปุ่มอื่น**
- **Scrape** ดึงข้อมูลอย่างเดียว (ทำต่อจากเดิม ไม่เริ่มชุดใหม่)
- **Score** ให้คะแนนชุดปัจจุบันใหม่ ไม่ใช้เน็ต ใช้เมื่อแก้วิธีให้คะแนน
- **จำนวนประกาศสูงสุด** ลดลงได้เมื่ออยากลองเร็ว ๆ เช่น 5 ประกาศ ใช้ราว 3 นาที **ระวัง:** บนชุดที่ครบแล้ว Run all จะเก็บชุดเดิมเข้า `output_archive/` ก่อนเสมอ และเก็บแค่ 3 ชุด ถ้าลองเกิน 3 ครั้ง ชุด 100 ประกาศที่ส่งมาจะถูกลบ อยากเก็บไว้ถาวรให้คัดลอกโฟลเดอร์ `output/` ไปไว้ที่อื่นก่อน

**ข้อควรรู้**
- หน้าเว็บต้นทางคือ "รถมาใหม่วันนี้" ข้อมูลจึงเปลี่ยนทุกวัน
- รันได้ทีละหนึ่งงานต่อโฟลเดอร์ ถ้ามีงานรันอยู่แล้ว ระบบจะปฏิเสธงานใหม่ ถ้าเครื่องดับกลางงานแล้วระบบบอกว่ายังมีงานรันอยู่ ให้ลบไฟล์ `output.running`
- ถ้าเว็บต้นทางบล็อก (AWS WAF) ระบบจะหยุดและเก็บงานไว้ กด Run all อีกครั้งภายหลังเพื่อทำต่อ
- ครั้งแรกที่ให้คะแนน ระบบจะโหลดโมเดล MUSIQ (~104MB) และ CLIP (~600MB) มาเก็บในเครื่อง

## 6. ตอบโจทย์แต่ละส่วนยังไง

### สิ่งที่ส่งมอบ

| โจทย์ | อยู่ที่ |
|---|---|
| Source code | `src/taladrod/`, `app.py` |
| Image folder (โฟลเดอร์เดียว) | `output/images/` ชื่อไฟล์ `{ad_id}_{index:02d}.jpg` (ไม่ชนกันข้ามประกาศ) |
| JSON | `output/taladrod_data.json` |

```
                 ┌────────────── Phase 1: เก็บข้อมูล (ใช้เน็ต) ──────────────┐
taladrod.com ──▶ │ list page (SchDataJSON) ─▶ detail pages ─▶ images         │
                 │ delay 1.5–3s · retry/backoff · WAF-aware · resume ได้      │
                 └───────────────┬───────────────────────────────────────────┘
                                 ▼
                 output/raw_ads.jsonl  +  output/images/{ad_id}_{NN}.jpg  (โฟลเดอร์เดียว)
                                 │
                 ┌───────────────▼──────── Phase 2: วิเคราะห์ (ไม่ยิงเว็บต้นทาง) ───────────┐
                 │ categorize ─▶ MUSIQ (คะแนนคุณภาพ) + CLIP (ชนิดรูป, ประเภทรถจากรูป)     │
                 │ ─▶ duplicate check ─▶ cover pick ─▶ Pydantic validation                │
                 └───────────────┬────────────────────────────────────────────────────────┘
                                 ▼
                 output/taladrod_data.json  ──▶  Streamlit dashboard / CLI
```

Phase 1 กับ Phase 2 แยกกันผ่านไฟล์ checkpoint ถ้าต้องการปรับวิธีให้คะแนนแล้วรันใหม่ ไม่ต้องยิงเว็บซ้ำ (งานนี้เปลี่ยนวิธีให้คะแนนหนึ่งครั้งหลังเห็นผลจริง โดยไม่ต้อง scrape ใหม่)

### ส่วนที่ 1: การดึงข้อมูล

**สิ่งที่พบจากการสำรวจเว็บจริง** ([docs/recon.md](docs/recon.md))
- หน้ารายการ **ฝังผลลัพธ์ทั้งหมดไว้ใน HTML** เป็นตัวแปร `SchDataJSON` (~220 คันต่อวัน) แล้วใช้ JavaScript แสดงทีละ 10 คันตอนเลื่อนจอ (infinite scroll) **ไม่มี pagination ฝั่ง server** จึงใช้ `requests` ธรรมดาได้ ไม่ต้องใช้ Playwright และเร็วกว่า
- Encoding เป็น UTF-8 (มีโค้ดสำรองไว้เผื่อหน้าไม่ระบุ charset)
- เว็บอยู่หลัง **AWS WAF** ถ้ายิงถี่เกิน (~20 request ใน 12 วินาที) จะได้ `HTTP 202` + `x-amzn-waf-action: challenge`

**วิธีเลือกประกาศ (Selection strategy)**
เลือก **ตามลำดับที่หน้า "รถมาใหม่วันนี้" แสดง** (ใหม่สุดก่อน) ไล่ทีละหน้า หน้าละ 10 คัน (ขนาดเดียวกับที่เว็บใช้) จนครบ `MAX_ADS` (≤ 100) หรือข้อมูลหมด ข้อความนี้อยู่ใน `config.SELECTION_STRATEGY` และถูกบันทึกลง `meta.selection_strategy` ของ JSON ทุกครั้ง

ชุดข้อมูลที่ส่งมาเก็บจากหลายรอบในวันเดียวกันโดยใช้ resume ประกาศใหม่ที่ขึ้นหน้าเว็บระหว่างวันจึงถูกเก็บมาด้วย Phase 2 ใช้ 100 ประกาศแรกที่เก็บได้ใน checkpoint

**ข้อมูลที่เก็บต่อประกาศ**
Ad ID, ยี่ห้อ, รุ่น, ปี (แปลง พ.ศ. เป็น ค.ศ. อัตโนมัติ), ราคา, เลขไมล์ (ถ้าไม่มีจะเป็น `null` ชุดนี้มี 1 ประกาศ), ลิงก์ประกาศ และรูปทุกรูปพร้อม URL ต้นทางรายรูป ระบบกรองรูป "รถคันอื่นที่คล้ายกัน" ที่อยู่ในหน้าเดียวกันออกด้วย โดยดูจาก prefix ของรูปประจำประกาศ

**ความเสถียร (Reliability)**
- **Delay** สุ่ม 1.5–3.0 วินาที ก่อนทุก request
- **Retry** 4 ครั้ง แบบ exponential backoff (1, 2, 4, 8 วินาที) สำหรับ timeout, connection error, 429, 5xx
- **WAF challenge**: รอเพิ่มอีก 30 วินาทีแล้วลองใหม่ ถ้ายังโดนอยู่จะ **หยุดอย่างปลอดภัย** และเก็บ checkpoint ไว้ ไม่พยายามหลบหรือแก้ challenge
- **Checkpoint/Resume**: เขียน `raw_ads.jsonl` ทีละประกาศ รันใหม่จะข้ามประกาศที่มีแล้ว
- **กันรันซ้อน**: ไฟล์ `output.running` ทำให้มีงานเขียนโฟลเดอร์เดียวกันได้ทีละงาน
- รูปที่โหลดไม่ได้จะไม่ทำให้งานล้ม แต่จะบันทึก `error` ไว้ในรูปนั้น

### ส่วนที่ 2: การจัดหมวดหมู่
เว็บไม่มีฟิลด์ประเภทตัวถัง จึงใช้ logic ตามลำดับนี้ (`src/taladrod/categorizer.py`):
1. ถ้าแหล่งข้อมูลให้ประเภทตัวถังมา ให้ใช้ค่านั้นเลย (`category_source: "site"`) เตรียมไว้สำหรับแหล่งข้อมูลอื่นในอนาคต
2. **Dictionary รุ่นรถในตลาดไทย** ~250 รุ่น เช่น Revo/D-Max/Ranger เป็นกระบะ, Fortuner/MU-X/CR-V/X1 เป็น SUV/PPV, Alphard/Commuter/Staria เป็นรถตู้/MPV จับคู่แบบทั้งคำ และให้ชื่อที่ยาวกว่ามาก่อน เช่น `COROLLA CROSS` ถูกจับก่อน `ALTIS` รหัสรุ่น 2 ตัวอักษร (ZS, LM, X1) ใช้เทียบกับฟิลด์ model เท่านั้น จะได้ไม่ชนกับชื่อ trim ถ้ายังไม่เจอ จะดูคำที่ผู้ขายเขียน เช่น "กระบะ", "CAB", "SUV" (`"dictionary"`)
3. ไม่เข้าเงื่อนไขใดเลยได้ `อื่นๆ` (`"fallback"`)

หมวด: `เก๋ง`, `กระบะ`, `SUV/PPV`, `รถตู้/MPV`, `อื่นๆ` ทุกประกาศมี `category_source` บอกว่าได้หมวดมาจากไหน ตรวจสอบได้ และมีการตรวจซ้ำด้วยรูป (หัวข้อ 7 ข้อ 2)

### ส่วนที่ 3: การประเมินคุณภาพรูปด้วย AI (Local)

**แนวทางที่เลือก: Deep Learning IQA ด้วย MUSIQ** (ผ่าน `pyiqa`, weights ที่เทรนกับ KonIQ-10k) **รันบนเครื่องทั้งหมด ไม่เรียก API ภายนอก**

`quality_score = คะแนน MUSIQ (0–100) ÷ 10` ปัดทศนิยม 1 ตำแหน่ง ไม่ยืดสเกล คะแนนดิบอยู่ใน `quality_breakdown.musiq`

**วิธีเลือก: ทดลอง 4 วิธีบนรูปจริงชุดเดียวกัน**
โจทย์ขอให้คะแนน "อธิบายได้และสมเหตุสมผลเมื่อเทียบกับภาพจริง" จึงให้คะแนนรูป 1,320 รูปที่ดึงมาด้วย 4 วิธี แล้วเปิดดูรูปคะแนนต่ำสุด กลาง และสูงสุดของแต่ละวิธี

| # | วิธี | สิ่งที่เห็นในรูปจริง | ผล |
|---|---|---|---|
| 1 | CLIP-IQA (prompt คู่ตรงข้าม 3 ปัจจัย) เวอร์ชันแรกของงานนี้ | รูปกระบะด้านข้างเต็มคัน คมชัด ได้ 3.2 · รูปเบาะได้ "องค์ประกอบ" 10.0 · ความคมชัดสัมพันธ์กับ Laplacian เพียง 0.19 ([ต่ำสุด](docs/iqa_experiment/1_clip_iqa_lowest.jpg), [สูงสุด](docs/iqa_experiment/1_clip_iqa_highest.jpg)) | ไม่ผ่าน |
| 2 | Hybrid: OpenCV (re-blur, exposure) + CLIP framing | รูปคะแนนต่ำสมเหตุสมผล แต่ห้องเครื่องและรูปตัดต่อได้ 10.0 ค่ากลาง 9.3 แยกรูปดีไม่ออก ([ต่ำสุด](docs/iqa_experiment/2_hybrid_lowest.jpg), [สูงสุด](docs/iqa_experiment/2_hybrid_highest.jpg)) | ไม่ผ่าน |
| 3 | NIMA | เป็นโมเดลความสวยงาม จัดรูปรถด้านข้างเต็มคันไว้ต่ำสุด รูปภายในไว้สูงสุด ([รูป](docs/iqa_experiment/3_nima_low_mid_high.jpg)) | ไม่ผ่าน |
| 4 | **MUSIQ** | ต่ำสุด: จอมืด กระจกหลังคา สติกเกอร์ ชิ้นส่วนระยะใกล้ · สูงสุด: รถเต็มคัน คม แสงดี ([รูป](docs/iqa_experiment/4_musiq_low_mid_high.jpg)) | **เลือก** |

**ทำไม MUSIQ**
- เทรนจากคะแนนที่คนให้กับรูปถ่ายจริง คะแนนเดียวจึงรวมความคมชัด แสง และการจัดภาพตามที่คนมอง ซึ่งตรงกับผลที่เห็นในรูป
- รันบน CPU ได้ ต้นทุนต่อรูปคงที่ (ราว 0.5 วินาทีต่อรูป รวม CLIP) ตรงกับเหตุผลที่โจทย์ห้ามใช้ API ภายนอก
- เป็นแนวทาง "Deep Learning IQA" ที่โจทย์ยกตัวอย่างไว้

**สิ่งที่แลกมา**
- ได้คะแนนรวมตัวเดียว ไม่มีคะแนนแยกความคมชัด/แสง/องค์ประกอบ ค่า OpenCV (Laplacian variance, ความสว่างเฉลี่ย) ยังบันทึกใน `raw_metrics` ให้ตรวจเทียบได้ แต่ไม่ได้นำมาคิดคะแนน
- ช่วงคะแนนแคบ (5.3–7.9) เพราะรูปจากเต็นท์รถคุณภาพใกล้กัน จึงเหมาะกับการเรียงลำดับและคัดรูปท้ายแถว มากกว่าตีความตัวเลขเดี่ยว ๆ

**บทเรียน:** CLIP ตัดสิน *คุณภาพ* ได้ไม่ดี แต่บอก *เนื้อหา* ของรูปได้แม่น งานนี้จึงย้าย CLIP ไปทำหน้าที่จำแนกชนิดรูปแทน (หัวข้อ 7 ข้อ 1–2)

ไฟล์รูปที่เสียหรือเปิดไม่ได้จะได้ `quality_score: 0.0` พร้อม `error` และ batch ยังทำงานต่อได้ เหตุผลทั้งหมดอยู่ใน docstring ของ `src/taladrod/iqa.py` ด้วย

## 7. ฟีเจอร์เพิ่มเติมนอกโจทย์
1. **จำแนกชนิดรูปด้วย CLIP (local, zero-shot)**: ทุกรูปมี `view_type` (ภายนอก / ภายใน / ห้องเครื่อง / ชิ้นส่วนระยะใกล้ / เอกสาร-อื่นๆ) ใช้อธิบายว่าทำไมรูปได้คะแนนต่ำ และใช้คัดรูปปก ([ตัวอย่าง](docs/iqa_experiment/clip_view_types.jpg))
2. **ตรวจประเภทรถจากรูป**: CLIP ดูเฉพาะรูปภายนอกแล้วทายประเภทรถ เทียบกับ dictionary ถ้าไม่ตรงและมั่นใจ ≥ 0.6 จะติดธง `category_mismatch` ให้คนตรวจ **ไม่เขียนทับ `category`** ในชุดนี้ตรงกัน 87 จาก 96 ประกาศ ติดธง 2: ORA 07 (dictionary จัดเป็น SUV แต่รูปเป็นเก๋งทรง fastback: AI ถูก) และ Alphard (AI ทายเป็น SUV: AI ผิด) ประกาศที่ dictionary ไม่รู้จัก (`อื่นๆ`) จะได้คำแนะนำจากรูป เช่น Soluna, Fiat 500 เป็นเก๋ง
3. **เลือกรูปปกอัตโนมัติ** (`cover_image`): รูปภายนอกที่คะแนนสูงสุดและไม่ซ้ำ ในชุดนี้ได้รูปภายนอกครบ 100 ประกาศ ([ตัวอย่าง](docs/iqa_experiment/auto_covers.jpg))
4. **ตรวจรูปซ้ำ** ด้วย perceptual hash ทั้งในประกาศเดียวกันและข้ามประกาศ (ดีลเลอร์มักใช้รูปซ้ำ) ผลอยู่ใน `is_duplicate_of` ชุดนี้พบ 15 รูป
5. **ดึงชุดใหม่ปุ่มเดียว + เก็บชุดเก่าอัตโนมัติ**: Run all บนชุดที่ครบแล้วจะเก็บชุดเดิมและเริ่มชุดใหม่ เก็บ 3 ชุดล่าสุด เตือนก่อนลบ และเตือนเมื่อดิสก์ใกล้เต็ม (หัวข้อ 4)
6. **Streamlit dashboard**: กดรันได้พร้อมแถบความคืบหน้า มีภาพรวม, ตัวกรองประกาศ (ประเภท/ราคา/คะแนน/ค้นหา/เฉพาะที่ประเภทไม่ตรงกับรูป), แกลเลอรีของแต่ละประกาศ, หน้า "รูปที่ควรถ่ายใหม่", ตัวเลือกดูชุดเก่า และปุ่มดาวน์โหลด JSON
7. **Resume ได้ + รับมือ WAF + กันรันซ้อน**: หยุดกลางทางแล้วรันต่อได้ และไม่มีสองงานเขียนข้อมูลชุดเดียวกัน
8. **`run.bat`**: เริ่มใช้งานบน Windows ด้วยการดับเบิลคลิก

## 9. แก้ปัญหา ข้อจำกัด และแนวทางต่อยอด

### แก้ปัญหา
- **`run.bat` บอกว่าไม่พบ Python**: ติดตั้ง Python 3.10+ จาก python.org และติ๊ก "Add python.exe to PATH" แล้วเปิดใหม่
- **ติดตั้งล้มด้วย `No such file or directory`**: path ของโฟลเดอร์ยาวเกิน ย้ายโปรเจกต์ไป path สั้น ๆ แล้วเปิด `run.bat` ใหม่
- **ระบบบอกว่ามีงานรันอยู่ ทั้งที่ไม่มี**: เครื่องดับหรือโปรแกรมถูกปิดกลางงาน ให้ลบไฟล์ `output.running`
- **กด Run all แล้วบอกว่าย้ายโฟลเดอร์ไม่ได้**: มีโปรแกรมเปิดไฟล์ใน `output/` ค้างอยู่ (โปรแกรมดูรูป, Explorer) ปิดแล้วกดใหม่ ข้อมูลเดิมยังอยู่ครบ
- **`RuntimeError: Numpy is not available` ตอนให้คะแนน**: PyTorch ในเครื่องคอมไพล์กับ NumPy 1.x ให้ใช้ venv ใหม่ (`run.bat` ทำให้อยู่แล้ว)
- **`ImportError: numpy.core.multiarray failed to import` / `_ARRAY_API not found` ตอน `import cv2`**:
  มี OpenCV รุ่นเก่า (คอมไพล์กับ NumPy 1.x) ค้างอยู่ ให้รัน
  `pip uninstall -y opencv-python opencv-contrib-python opencv-python-headless` แล้ว
  `pip install "opencv-python-headless>=4.10.0.84"` (หรือใช้ venv ใหม่)

### ข้อจำกัด
- โครงสร้างหน้าเว็บอาจเปลี่ยน ถ้า `SchDataJSON` หายไป parser จะ error พร้อมข้อความชัดเจน (`ParseError`) ไม่เงียบ
- ถ้าโดน WAF challenge ต่อเนื่อง รอบนั้นอาจได้ไม่ถึง 100 ประกาศ ให้กด Run all ซ้ำทีหลังเพื่อทำต่อ
- ถ้าวันใดเว็บมีประกาศน้อยกว่าจำนวนที่ตั้งไว้ ระบบจะมองว่าชุดนั้นยังไม่ครบ และ Run all จะทำต่อแทนการเริ่มชุดใหม่
- ความแม่นของการจัดหมวดขึ้นกับ dictionary รุ่นที่ยังไม่อยู่ในรายการจะเป็น `อื่นๆ` ซึ่งดูได้จาก `category_source`
- MUSIQ ไม่ได้ fine-tune กับรูปรถ คะแนนเหมาะใช้เปรียบเทียบเชิงสัมพัทธ์ และไม่มีคะแนนแยกรายปัจจัย
- การทายประเภทรถจากรูปยังผิดได้ โดยเฉพาะกระบะ 4 ประตูกับ SUV (ถูก 7 จาก 10) จึงใช้เป็นธงให้คนตรวจเท่านั้น
- การตรวจผลด้วยตาทำกับรูปปลายแถวและกลางแถวของแต่ละวิธี ไม่ได้ติดป้ายกำกับทั้ง 1,320 รูป

### แนวทางต่อยอด
- เปลี่ยน `pipeline.py` เป็น FastAPI service ได้ทันที เพราะ logic แยกจาก UI แล้ว
- ตั้งเวลารันรายวัน แล้วใช้ชุดใน `output_archive/` เทียบราคาข้ามวันเพื่อดูแนวโน้ม
